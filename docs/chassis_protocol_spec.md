# 车体动作与状态处理规范

SlamTest 底盘 <-> 上位机（树莓派 / PC）之间数据交换的唯一约定。

**本文件是协议的唯一权威来源。** 代码与本文件不符时，以本文件为准并修改代码。

用词效力：

- **必须 / 不得** —— 违反即为 bug，必须修。
- **应当 / 不应** —— 默认遵守；确需偏离时，必须在代码注释里写明理由。

---

## 1. 坐标系

车体基座系 **B** 为右手系：

| 轴 | 正方向 |
|---|---|
| x | 前 |
| y | 左 |
| z | 上 |

满足 `ex × ey = ez`。

对外（上位机可见）的物理量一律在 B 系下解释：

- `+vx` = 车头方向
- `+wz` = 逆时针（俯视，即左转）

与 ROS REP-103 一致。

底盘内部坐标系（电机极性、编码器极性、PID、航向环标定）不得对外暴露。
内外转换只允许发生在 `Lib/Src/kinematics.c` 的两个符号宏：

```c
#define CHASSIS_V_SIGN   (-1.0f)
#define CHASSIS_W_SIGN   (+1.0f)
```

且只能作用于三处：

- 命令入口 `Chassis_Set_Cmd()`
- 反馈出口 `Chassis_GetVx_MmS()` / `Chassis_GetWz_MradS()`
- 反馈出口 `Chassis_GetWheels_MmS()`

**不得**在其它任何地方再翻一次符号。改方向只改这两个宏。

## 2. 单位

线路上所有数值字段一律使用下列单位，**不得**混用：

| 物理量 | 线路单位 | 备注 |
|---|---|---|
| 线速度 | `mm/s` | 不是 m/s |
| 角速度 | `mrad/s` | 不是 rad/s |
| 转角 | `0.01 度` | 即 100 倍度 |
| 电压 | `mV` | |
| 轮距 / 轮径 | 米 | 仅固件运动学内部使用，不上线路 |

整数一律**大端**、**有符号**（除非字段定义里写明无符号）。

## 3. 下行控制帧（上位机 -> 底盘，11 字节）

| 偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 1 | `0x7B` |
| 1 | 2 | 预留，**必须**填 0 |
| 3 | 2 | `X` 线速度 mm/s，前进为正 |
| 5 | 2 | `Y` 线速度 mm/s，差速车**必须**填 0 |
| 7 | 2 | `Z` 角速度 mrad/s，逆时针（左转）为正 |
| 9 | 1 | BCC = 前 9 字节异或 |
| 10 | 1 | `0x7D` |

上位机**必须**：

- 以 **20 ~ 50 Hz** 重复发送。AUTO 模式 200 ms 收不到新包即自动减速停车。
- 停车时也**必须**持续发送 `X=0, Z=0`；**不得**用「停止发送」来停车。
- 知晓：收到任一合法下行帧即会让底盘切入 AUTO 模式并拒绝手柄命令；手柄 START 键交还手动控制。

## 5. 冗余量的一致性约束

上行帧里 `vx`、`wz`、`vl`、`vr` 是同一份数据的两种表达，**必须**始终满足：

```
vx = (vl + vr) / 2
wz = (vr - vl) / 轮距
```

因此：

- 上位机**不得**由 `vx`/`wz` 反推 `vl`/`vr`。
- 上位机**不得**自带轮距常数。`vl`/`vr` 字段就是为此而设的。
- 固件侧四个量**必须**同源（都取 `actual_pulse` + `CHASSIS_V_SIGN`），不得一个用滤波值、另一个用原始值。

---

## 6. 物理常量的单一权威来源

轮距、轮径、编码器线数、控制周期等物理常量**只允许**定义在
`Lib/Src/kinematics.c` 一处。

上位机**不得**复制这些常量。若某个量上位机确实需要，**必须**由固件放进上行帧下发
（例如 `vl`/`vr` 就是为了让上位机不必知道轮距）。

判断标准很简单：**如果固件改了这个数而某个上位机文件需要跟着改，那这个设计就是错的。**

---

## 7. 换算只在一层

**固件侧**：线路单位（mm/s、mrad/s）与内部物理量（m/s、rad/s）之间的换算，
只允许出现在 `Lib/Src/protocol.c`：

- 收：`Protocol_Push_Byte()` 里 `mm/s -> m/s`、`mrad/s -> rad/s`
- 发：`main.c` 组帧处 `* 1000.0f`，以及 `protocol.c` 的 `Protocol_ClampI16()`

**上位机侧**：只允许出现在两个地方：

- 命令方向：`chassis_link_test.py` 的 `ACTION` 表
- 反馈方向：`chassis_link_test.py` 的 `decode()`

其它函数**不得**再引入一次 `* 1000` 或 `/ 1000`。

---

## 8. 帧布局变更规则

- 上行帧新增字段**必须**追加在 `status` 之后、BCC 之前。
  偏移 `0..30` 的既有含义**不得**变动。
- 任何帧长或布局变更，**必须**同步修改下列全部位置，缺一不可：

| # | 文件 | 要改什么 |
|---|---|---|
| 1 | `Lib/Inc/protocol.h` | 布局注释表 + `Protocol_Feedback_t` 成员 |
| 2 | `Lib/Src/protocol.c` | `TX_LEN` / `RX_LEN` + 组帧语句 |
| 3 | `Core/Src/main.c` | 填新字段 |
| 4 | 上位机 `chassis_link_test.py` | `FRAME_RX` + 校验偏移 + `decode()` |
| 5 | 上位机 `check.py` | `FRAME_RX` + 校验偏移 + `parse()` |
| 6 | 上位机 `pi_check.py` | 同上 |

- 改完**必须**跑 `tools/verify_protocol.py` 自检（见 §9）。

## 9. 自检清单

每次动协议后逐条确认：

- [ ] `protocol.h` 布局注释、`protocol.c` 的 `TX_LEN`、三个上位机脚本的 `FRAME_RX` 都是同一个数
- [ ] `python tools/verify_protocol.py` 全项通过
- [ ] 上位机侧不存在第二份轮距/轮径常量
- [ ] 实车验证 `fwd` / `back` / `spin` 方向正确（`spin` 取正必须逆时针）
- [ ] 上下行仍在 20~50 Hz 稳态收发，坏帧为 0

## 10. 变更历史（含一次真实事故）

| 日期 | 上行帧长 | 说明 |
|---|---|---|
| 2026-09 | 24 字节 | 初版：stop/vx/vy/wz/acc/gyro/batt |
| 2026-09 | 33 字节 | OLED 拆除，YAW / Ry / E / Wc 与 status 改由 USART1 下发 |
| 2026-09-15 | **37 字节** | 增加 `vl_mm_s` / `vr_mm_s`，消除上位机侧的轮距重复定义 |

**事故记录**：24 -> 33 字节那次改动，只改了固件，没有同步上位机。
结果 `chassis_link_test.py`、`check.py`、`pi_check.py` 三个解析脚本全部
按 24 字节解析 33 字节的流，**静默失效** —— 不报错，只是再也收不到帧。
这正是「§8 六处必须同步」和「§9 自检必须跑」这两条的由来。

## 附：为什么不做自动单位换算

1. 数据里没有单位信息。一个数 `0.3` 自己不知道是 m/s 还是 mm/s；要自动换算，
   先得知道源单位，而源单位只能靠人声明。
2. 部分语义根本无法自动换算（例如左右关节排列顺序、夹爪开合方向）。
   既然总有一部分必须人工声明，不如规则单一：全部由发送方按本规范准备好。
3. 静默错误最贵。错误的单位会被限幅和归一化掩盖，直到实车才暴露；
   而「不合规就发不出」是硬失败，当场可见。
4. 换算点数量：N 个生产者 x M 个消费者 = NxM 个换算点；强制在源头转一次只有 N 个。

结论：这不是性能取舍，是**责任归属** —— 谁最清楚数据的单位，谁负责转。
