# 车体动作与状态处理规范

SlamTest 底盘 <-> 上位机（树莓派 / PC）之间数据交换的唯一约定。

**本文件是协议的唯一权威来源。** 代码与本文件不符时，以本文件为准并修改代码。

用词效力：

- **必须 / 不得** —— 违反即为 bug，必须修。
- **应当 / 不应** —— 默认遵守；确需偏离时，必须在代码注释里写明理由。

---

## 1. 坐标系

车体基座系 **B** 为右手系：

| 轴 | 正方向 |
|---|---|
| x | 前 |
| y | 左 |
| z | 上 |

满足 `ex × ey = ez`。

对外（上位机可见）的物理量一律在 B 系下解释：

- `+vx` = 车头方向
- `+wz` = 逆时针（俯视，即左转）

与 ROS REP-103 一致。

底盘内部坐标系（电机极性、编码器极性、PID、航向环标定）不得对外暴露。
内外转换只允许发生在 `Lib/control/inc/kinematics.h` 的两个符号宏：

```c
#define CHASSIS_V_SIGN   (-1.0f)
#define CHASSIS_W_SIGN   (+1.0f)
```

且只能作用于三处：

- 命令入口 `Chassis_Set_Cmd()`
- 反馈出口 `Chassis_GetVx_MmS()` / `Chassis_GetWz_MradS()`
- 反馈出口 `Chassis_GetWheels_MmS()`

**不得**在其它任何地方再翻一次符号。改方向只改这两个宏。

## 2. 单位

线路上所有数值字段一律使用下列单位，**不得**混用：

| 物理量 | 线路单位 | 备注 |
|---|---|---|
| 轮速 | `r/min` | 速度指令与状态回报都用它 |
| 线速度 | `mm/s` | 只在运动学内部换算，不上线路 |
| 角速度 | `mrad/s` | |
| 转角 | `0.01 度` | 即 100 倍度 |
| 电压 | `mV` | |
| PID 增益 | `0.001` | 线上整数 = 实际浮点 × 1000 |

多字节整数一律**小端**、**有符号补码**（除非字段定义里写明无符号）。

## 3. 帧格式

```text
AA 55 | payload_len(1) | msg_id(1) | seq(1) | payload(N) | CRC16(2)
```

| 字段 | 长度 | 说明 |
|---|---:|---|
| 帧头 | 2 B | 固定 `AA 55`，用于从任意错位处重新对齐 |
| 载荷长度 | 1 B | **只算 payload**，不含帧头、长度、ID、序号、CRC |
| 消息 ID | 1 B | 见 §4 |
| 序列号 | 1 B | 0~255 循环，用于观察丢帧 |
| 载荷 | N B | 最大 32 B |
| CRC16 | 2 B | CRC-16/MODBUS，低字节先发 |

整帧长度 = `7 + payload_len`。

### CRC 参数

| 项 | 值 |
|---|---|
| 算法 | CRC-16/MODBUS |
| 多项式 | 反射式 `0xA001`（即标准 `0x8005` 的反射写法） |
| 初值 | `0xFFFF` |
| 输入反射 | 是 |
| 输出反射 | 是 |
| 最终异或 | 无 |
| 覆盖范围 | 帧头 `AA` 到载荷最后一个字节，**不含 CRC 本身** |
| 发送顺序 | CRC 低字节在前 |

参考自检：CRC-16/MODBUS 对 ASCII `123456789` 应得到 `0x4B37`。

### 长度上限与重同步

- `payload_len > 32` 的帧直接判坏帧，丢弃并回到找帧头状态。
- 任意阶段出错，都从当前字节重新找 `AA`；如果当前字节本身就是 `AA`，
  直接把它当作下一帧的帧头，不浪费。
- 帧内字节间隔超过 50 ms，判半截帧超时，`timeout_cnt++` 并回到找帧头状态。

## 4. 消息 ID

| ID | 方向 | 名称 | 载荷 | 频率 |
|---|---|---|---|---|
| `0x01` | 上位机 → MCU | 速度指令 | `left_rpm int16`, `right_rpm int16` | 20~50 Hz |
| `0x02` | MCU → 上位机 | 状态回报 | 24 B，见 §5 | 50 ms |
| `0x03` | 上位机 → MCU | 清计数 | `magic uint8 = 0x5A` | 按需 |
| `0x10` | MCU → 上位机 | 轮速遥测 | 12 B，见 §6 | 20 ms |
| `0x11` | 上位机 → MCU | PID 预设 | `preset uint8`：0=P, 1=PI, 2=PID | 按需 |
| `0x12` | 上位机 → MCU | PID 增益 | 6 × `int16`，单位 0.001 | 按需 |

未知消息 ID **忽略但不算坏帧**，方便以后加新 ID 而不破坏旧固件。

---

## 5. 状态帧 `0x02`（payload 24 B）

| 偏移 | 长度 | 字段 | 单位 / 说明 |
|---:|---:|---|---|
| 0 | 2 | `left_rpm` | 左轮实测 r/min，`int16` |
| 2 | 2 | `right_rpm` | 右轮实测 r/min，`int16` |
| 4 | 2 | `pitch_001deg` | 俯仰角，0.01°，`int16` |
| 6 | 2 | `yaw_001deg` | 偏航角，0.01°，`int16` |
| 8 | 2 | `heartbeat` | 心跳计数，`uint16`，每帧 +1 |
| 10 | 2 | `bad_frame_cnt` | CRC 错 / 长度非法累计，`uint16`，饱和不回绕 |
| 12 | 2 | `timeout_cnt` | 半截帧超时累计，`uint16`，饱和不回绕 |
| 14 | 2 | `overflow_cnt` | 环形缓冲溢出累计，`uint16` 上报（内部 32 位，饱和到 `0xFFFF`） |
| 16 | 1 | `status` | 见下 |
| 17 | 1 | `reserved` | 保留，填 0 |
| 18 | 2 | `battery_mv` | 电池电压 mV，`uint16`，0=未接 |
| 20 | 2 | `yaw_rate_mrad_s` | 偏航角速率，mrad/s，`int16` |
| 22 | 2 | `yaw_hold_out_mrad_s` | 航向环输出，mrad/s，`int16` |

`status` 位定义：

| 位 | 含义 |
|---|---|
| bit0 | 1 = 200 ms 内收到过合法速度帧（链路存活） |
| bit1 | 1 = IMU 可用 |
| bit2 | 1 = 电机使能 |
| bit3~7 | 保留，填 0 |

计数器语义：

- 上电清零。
- 只有收到 `0x03` 且 magic 正确时才清零。
- 计到 `0xFFFF` 后保持，不回绕；否则长时间垃圾流会把“坏帧很多”显示成“坏帧 0”。

---

## 6. 遥测帧 `0x10`（payload 12 B）

给 M4-3 采集 PID 阶跃曲线用，和状态帧分开，避免 50 ms 状态帧被高频数据撑大。

| 偏移 | 长度 | 字段 |
|---:|---:|---|
| 0 | 2 | `target_rpm_L` |
| 2 | 2 | `actual_rpm_L` |
| 4 | 2 | `pwm_L`（PID 输出，范围 -100~100） |
| 6 | 2 | `target_rpm_R` |
| 8 | 2 | `actual_rpm_R` |
| 10 | 2 | `pwm_R` |

全部 `int16`，小端。

---

## 7. PID 预设与增益帧

### `0x11` PID 预设

载荷 1 字节：

| 值 | 含义 |
|---:|---|
| 0 | 纯 P |
| 1 | PI |
| 2 | PID |

### `0x12` PID 增益

载荷 12 字节，顺序固定：

```text
L Kp, L Ki, L Kd, R Kp, R Ki, R Kd
```

每个都是 `int16`，线上值 = 实际值 × 1000。例如实际 `Kp = 1.2`，线上写 `1200`。

---

## 8. 超时与停车

- 上位机**必须**以 20~50 Hz 重复发送 `0x01`。
- MCU 200 ms 没收到合法速度帧：自动下发 `(0,0)`，`status.bit0 = 0`。
- 停车时也**必须**持续发送 `left_rpm=0, right_rpm=0`；不得用“停止发送”来停车。
- 恢复发送后，下一帧合法速度帧立即恢复控制，`status.bit0` 回 1。

## 9. 示例帧

以下字节均为十六进制，CRC 已用独立实现复算过。

### 速度指令：左右轮各 60 r/min

```text
AA 55 04 01 00 3C 00 3C 00 10 15
│  │  │  │  │  └─┬─┘ └─┬─┘ └─┬─┘
│  │  │  │  │    │     │     └── CRC16 = 0x1510（低字节 10 先发）
│  │  │  │  │    │     └──────── 右轮 60 = 0x003C（小端 3C 00）
│  │  │  │  │    └────────────── 左轮 60 = 0x003C
│  │  │  │  └─────────────────── 序号 0
│  │  │  └────────────────────── 消息 ID 0x01
│  │  └───────────────────────── 载荷长度 4
│  └──────────────────────────── 帧头第二字节 0x55
└─────────────────────────────── 帧头第一字节 0xAA
```

### 状态帧（示例值）

字段：`left=60, right=62, pitch=1.23°, yaw=90.50°, heartbeat=1000,
bad=2, timeout=1, overflow=0, status=0x07, battery=12100 mV,
yaw_rate=1500 mrad/s, yaw_hold_out=-250 mrad/s`

```text
AA 55 18 02 00
3C 00 3E 00 7B 00 5A 23 E8 03 02 00 01 00 00 00
07 00 44 2F DC 05 06 FF
A8 9D
```

CRC = `0x9DA8`，低字节 `A8` 先发。

### 遥测帧（示例值）

字段：`target_L=60, actual_L=58, pwm_L=35, target_R=60, actual_R=61, pwm_R=33`

```text
AA 55 0C 10 00 3C 00 3A 00 23 00 3C 00 3D 00 21 00 EE 08
```

CRC = `0x08EE`。

### 清计数

```text
AA 55 01 03 00 5A 65 DA
```

### PID 预设为 PID（2）

```text
AA 55 01 11 00 02 C4 25
```

### PID 增益（左右相同：Kp=1.2, Ki=0.3, Kd=0.05）

```text
AA 55 0C 12 00 B0 04 2C 01 32 00 B0 04 2C 01 32 00 71 4E
```

## 10. 帧布局变更规则

任何帧长或布局变更，**必须**同步修改下列全部位置，缺一不可：

| # | 文件 | 要改什么 |
|---|---|---|
| 1 | `Lib/comm/inc/protocol.h` | 消息 ID、长度宏、布局注释、结构体 |
| 2 | `Lib/comm/src/protocol.c` | 组帧 / 解析 / CRC |
| 3 | `Core/Src/main.c` | 填新字段、发送周期 |
| 4 | 上位机 `chassis_link_test.py` | 组帧、拆帧、`decode()` |
| 5 | 上位机 `check.py` / `pi_check.py` | 同上 |
| 6 | `slam-car-hmi/bridge/chassis_driver.py` | ROS2 节点解析 |

改完**必须**跑：

```bash
python tools/verify_protocol.py
```

## 12. 工作模式切换（ASCII 命令通道）

一套固件同时支持 M4-2 / M4-3 / M4-4。上电默认模式由 `app_config.h` 的
`APP_BOOT_MODE` 决定（当前为 **1 = M4-2 采集模式**，接上串口就能看到 CSV）。

运行期切换走两条互不干扰的通道：

| 触发 | 方向 | 效果 |
|---|---|---|
| 收到 `AA` `55` | 上位机 → MCU | 切到**协议模式**（M4-3 / M4-4） |
| ASCII 行 `#M42 1` + 换行 | 上位机 → MCU | 切到**采集模式**（M4-2，100 Hz CSV） |
| ASCII 行 `#M42 0` + 换行 | 上位机 → MCU | 切回**协议模式** |

**为什么不会误判**

- 采集模式的 CSV 全是可打印 ASCII，数据流里不可能出现 `0xAA`；
  所以"看到 `AA 55` 就切协议"不会被 CSV 自己触发。
- 反过来，二进制帧里要连续出现 `#M42 1\n` 这 7 个字节才会误切，
  概率可以忽略，而且切错只要重新上电就回到默认模式。
- 两条 `#M42` 命令都是 ASCII，与既有二进制帧头不重叠，也不是新的帧类型，
  所以 **§4 的消息 ID 表不变，§10 的六处同步规则不变**。

**切换时的清理动作**（`Lib/app/src/app_mode.c`）

- 切到采集模式：先 `Chassis_Set_Wheel_Rpm(0,0)` 停车，再重估 gyro 零偏。
- 切回协议模式：中止在途的 CSV 发送、清空环形缓冲、清解析器状态、停车。
- 两侧切换都会丢弃少量在途字节，因此切换瞬间可能出现 1~2 行残余 CSV
  或 1 个坏帧，属正常。

**上电时的例外**：`M42_Init()` 有 2 s 的静止标定窗口。如果这 2 s 内收到
`AA 55`，会立即放弃标定切到协议模式，不会把 M4-3/M4-4 的上位机卡住。

## 13. 变更历史

| 日期 | 变化 | 说明 |
|---|---|---|
| 2026-09 | 24 B 上行 | 初版：stop/vx/vy/wz/acc/gyro/batt |
| 2026-09 | 33 B 上行 | OLED 拆除，YAW / Ry / E / Wc 与 status 改由 USART1 下发 |
| 2026-09-15 | 37 B 上行 | 增加 `vl` / `vr`，消除上位机侧轮距重复定义 |
| 2026-11-21 | **新协议 v1.0** | 改为 `AA55 + len + id + seq + payload + CRC16`，状态帧 24 B，新增遥测/PID 帧 |
| 2026-11-21 | 运行期模式切换 | 增加 `#M42 0/1` 命令与 `AA55` 自动切换，一套固件通吃 M4-2/3/4；帧格式未变 |

**事故记录**：24 -> 33 字节那次改动，只改了固件，没有同步上位机。
结果三个解析脚本全部按 24 字节解析 33 字节的流，**静默失效** —— 不报错，
只是再也收不到帧。这正是“六处必须同步”和“自检必须跑”这两条的由来。

## 附：为什么不做自动单位换算

1. 数据里没有单位信息。一个数 `0.3` 自己不知道是 m/s 还是 mm/s；要自动换算，
   先得知道源单位，而源单位只能靠人声明。
2. 部分语义根本无法自动换算（例如左右关节排列顺序、夹爪开合方向）。
   既然总有一部分必须人工声明，不如规则单一：全部由发送方按本规范准备好。
3. 静默错误最贵。错误的单位会被限幅和归一化掩盖，直到实车才暴露；
   而“不合规就发不出”是硬失败，当场可见。
4. 换算点数量：N 个生产者 x M 个消费者 = N×M 个换算点；强制在源头转一次只有 N 个。

结论：这不是性能取舍，是**责任归属** —— 谁最清楚数据的单位，谁负责转。
